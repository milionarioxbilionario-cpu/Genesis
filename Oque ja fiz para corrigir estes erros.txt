Resumo do que foi validado até ao momento:

1. Autenticação e sessão
- Confirmei que o backend expõe o endpoint /api/auth/me.
- Sem cookie de sessão, a rota responde 401 Unauthorized.
- Com login válido do owner, o endpoint devolve os dados do utilizador autenticado.
- A autenticação via cookie httpOnly e JWT foi verificada com login real.

2. ProtectedRoute e redirecionamentos por role
- O frontend contém ProtectedRoute e protege owner/cashier.
- Acesso sem autenticação redireciona para /login.
- O admin principal foi reduzido a redireção para /login para evitar exposição do painel no frontend principal.

3. Separação do painel admin
- Verifiquei a presença do middleware backend adminOriginCheck.
- /api/admin rejeita origin inválida com 403.
- A origem autorizada no ambiente de desenvolvimento (http://localhost:5175) passa a validação de origin e exige autenticação.

4. QR code e recibos
- Os recibos geram QR code com a URL verificável /verify/[sale_id].
- A lógica foi validada no ficheiro frontend/src/utils/receiptPrinter.js.

5. Build e compilação
- Validação bem-sucedida:
  - npm run build no frontend
  - npm run build no admin-frontend
  - node --check no backend/src/index.js

6. Smoke tests de API
- GET / -> 200 OK
- GET /api/auth/me -> 401 quando não autenticado
- GET /api/admin sem origem correta -> 403 Forbidden
